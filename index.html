    Hardware

    The brain and the body

    Inference is memory-bandwidth-bound; agency is I/O-bound. Putting each on the silicon built for it keeps both cheap, quiet, and always on.

    NVIDIA DGX Spark

    The brain. A desk-side GB10 Grace Blackwell supercomputer holding the whole model resident in unified memory. No queues, no per-token bills, nothing leaves the apartment.

    • SuperchipGB10 Grace Blackwell
    • CPU20-core Arm (10× X925 + 10× A725)
    • GPU6,144 CUDA cores
    • AI Perf.~1 PFLOP FP4 sparse
    • Memory128 GB unified LPDDR5X
    • Bandwidth273 GB/s
    • Net10 GbE + 2× QSFP 200 Gbps

    NVIDIA Jetson Orin Nano

    The body. A palm-sized agent host that runs Hermes — sessions, tools, memory, skills, and every incoming connection — sipping 7–25 W 24/7 (measured idle: 6.9 W). It never loads a model; it just thinks it can.

    • CPU6-core Arm Cortex-A78AE
    • GPU1024 CUDA + 32 Tensor cores
    • AI Perf.67 INT8 TOPS
    • Memory8 GB LPDDR5
    • StorageNVMe, 456 GB
    • Power6.9 W idle · 7–25 W load
    • OSUbuntu 24.04 · L4T
    Connections

    Many doors, one brain

    Every door is a thin client. They all land on the same session store, the same memory, the same tools — so a conversation started on the phone at the grocery store resumes on the desktop at home, mid-sentence. Shut any door while work is running: the job finishes on the Orin and is done when you reopen.

    DoorPathWhat it's for
    Telegram (phone) bot API → gateway (systemd user service, linger, allowlisted DM) everyday reachability: anywhere there's signal. Voice notes transcribed, files and photos both ways.
    Desktop app (any OS) SSH connection → tunnel → loopback-only hermes serve full work surface: streaming tool timelines, session list, files — zero cloud, the app authenticates with an SSH key and starts the backend on demand.
    Terminal (ssh) ssh → hermes --tui / --resume power-user path from any machine in seconds — no install at all.
    No hands cron · background jobs · webhook triggers long agent runs the laptop never has to witness: start one from a phone, close the lid, read the result on Telegram in the morning.
    • Why it survives the shut-downAgent sessions run as processes detached from the connection that opened them (linger on, SSH tunnel is client-side only). Closing a laptop kills a keyboard, not a thought.
